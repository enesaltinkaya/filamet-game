## brainstorm

## Core difficulty

The DiligentFX SSAO library itself is nearly drop-in (c-engine already links `libDiligentFX.a`, already runs `PostFXContext` + TAA in the exact Tutorial27 shape, and `depthTex` D32 already carries `BIND_SHADER_RESOURCE`), so the hard parts are both on the engine side of the contract: (1) the render path has **no normal buffer at all** — SSAO's second mandatory input — and producing one means touching all three world raster passes (glTF PBR "player", heightmap terrain, props), including the DiligentFX `GLTF_PBR_Renderer` PS-footer surgery already used for TAA motion, while the shadow-pass PSO variants of the same shaders must NOT emit the new target; and (2) the AO result must be applied to the already-lit offscreen color in a way that composes with the render-scale chain, TAA's history, and the legacy (no-offscreen-chain) fallback path.

## Reductions / key lemmas

1. **SSAO reduces to a TAA-shaped problem.** `TaaDiligent.cpp` already does, every frame: `postFXContext->PrepareResources(device, FrameDesc{idx, tw, th, tw, th}, FEATURE_FLAG_NONE)` at render-scale size (lines 843-849) and `postFXContext->Execute(pa)` with camera CB + curr/prev depth + motion (lines 1121-1128). `ScreenSpaceAmbientOcclusion::Execute` (cpp:348) requires the *same* `PostFXContext*` plus `pDepthBufferSRV` (DEV_CHECK at cpp:354) + `pNormalBufferSRV` (cpp:355) + `pSSAOAttribs`. So the new module is a thin `SsaoDiligent.{h,cpp}` mirroring `TaaDiligent`'s lifecycle, reusing the existing context, the existing `depthTex[curr]` SRV (same one TAA passes at line 1125), and the existing camera CB. No second PostFXContext, no new frame machinery.

2. **Resolution invariance — AO output is 1:1 with `sceneColorTex`.** All SSAO intermediates are sized from the PostFXContext FrameDesc (= our render-scale target size). With `FEATURE_FLAG_HALF_RESOLUTION`: checkerboard depth + core AO run at half size (cpp:257-291), history textures stay full size, and `GetAmbientOcclusionSRV()` returns `ScreenSpaceAmbientOcclusion::UpsampledOcclusion`, a full-FrameDesc-size `R8_UNORM` (cpp:283-290). So AO compositing is a 1:1 texture multiply at exactly the resolution where TAA already operates — zero resize logic beyond TAA's.

3. **Normal buffer = one more RTV on an already multi-target pass, not a new pattern.** The world pass already binds 2 RTVs + DSV (DiligentRenderer.cpp:479-484). Adding a `normalTex` (RGBA16F — RGB16F is not a valid Vulkan RT; clear to (0,0,0,0)) as a 3rd RTV is pattern-identical to the motion RTV added for TAA. Per-shader, the world-space normal is already in scope: terrain VS explicitly outputs `float3 Normal : ATTRIB1; // world-space, border-aware stencil normal` (heightmap_terrain_vs.hlsl:55), so terrain PS `geomNormal = normalize(vs.Normal)` (ps:267) is directly the needed value; props PS has its lighting normal in scope (props_ps.hlsl:129, verify world-space transform); the glTF "player" pass already does PS-source surgery via `rendererCI.GetPSMainSource` (GltfDiligent.cpp:504-526) to add the TAA `SV_Target1` motion output — the same hook adds an `SV_Target2` world normal, provided the worker identifies the PS variable holding the final world-space normal in the GLTF_PBR source and gates the output on a PSO flag so the shadow-pass variant (which binds only dummy color+motion RTs, GltfDiligent.cpp:1129-1153) never writes it.

4. **Apply AO after TAA accumulation, not into the TAA input.** The DiligentFX reference multiplies AO into the diffuse/irradiance term (README formula); c-engine's resolve path has no per-pixel diffuse/specular split, so the practical application is a color multiply. SSAO owns its own temporal history + ReBLUR-style denoising (history textures, `TemporalStabilityFactor`, `SSAO_MAX_HISTORY_LENGTH 16` in the fxh), so the AO texture is already temporally stable — applying it *before* TAA would stack two competing history filters (TAA variance-rejection would fight AO disocclusion handling and smear AO via motion reprojection). Applying *after* `taa->Execute` (i.e. after line 1143 in `taaWorldResolve`, before the downsample/CAS/blit) is the standard placement and is a single small composite. Sky/background pixels: depth at far plane → AO≈1, harmless.

5. **Depth convention needs no new work.** `PostFXContext::FEATURE_FLAG_REVERSED_DEPTH` exists, but c-engine uses standard depth (DSV cleared to 1.0, LESS test → 0=near/1=far) and its TAA PostFXContext already runs with `FEATURE_FLAG_NONE`; the shared context is therefore correct for SSAO as-is.

6. **Toggling follows the TAA idiom.** Hydrogent gates on `SSAOScale > 0` (HnPostProcessTask.cpp:651). c-engine has the dangling `g.ssao` flag (Renderer.h:19, Renderer.cpp:234 reads `aoDisabled`, DebugGui.cpp:65/103, SettingsGraphicsGui.cpp:116). Mirror TAA's "prepare even while disabled so history resets on re-enable" (TaaDiligent.cpp:851-853 comment): call `ssao->PrepareResources` every frame (idempotent at stable size), call `Execute` + composite only when `g.ssao`.

7. **Verification hooks already exist in the library.** `Execute` wraps everything in `ScopedDebugGroup{...,"ScreenSpaceAmbientOcclusion"}` (cpp:363) with child groups ComputeDownsampledDepth / ComputeHierarchicalDepthBuffer / ComputeAmbientOcclusion / ComputeTemporalAccumulation / ComputeConvolutedDepthHistory / ComputeResampledHistory / ComputeSpatialReconstruction / ComputeBilateralUpsampling (cpp:834-1311) — so `scripts/rdc.py list` will show the pass by name; the engine should add its own `ScopedDebugGroup` "ssao" around the Execute call to match the existing pass naming (shadow/player/terrain/props/taa_resolve/gui/rmlui). `AlphaInterpolation` (fxh:89) and `EffectRadius` (fxh:67) give a ready intensity/radius knob for the settings GUI; `Algorithm` (fxh:94, values 0/1/2 = GTAO/HBAO/VBAO, consumed at cpp:361) gives the algorithm switch.

## Candidate approaches

**A. Thin SSAO module + normal RT + post-TAA composite (recommended).**
Sketch: `SsaoDiligent.{h,cpp}` mirroring `TaaDiligent`'s lifecycle; `normalTex` RGBA16F added to the offscreen chain and to the 2-RTV world pass (3 RTVs); `SV_Target2` world-normal output in terrain/props PS + glTF footer override; `ssao->PrepareResources(..., FEATURE_FLAG_HALF_RESOLUTION)` in the frame-begin; `Execute` after `postFXContext->Execute`, after the TAA block in `taaWorldResolve`; small composite (new intermediate + PS `out = in * (1 - (1-ao) * strength)`, or AO multiply folded into the existing blit/CAS PS) before CAS/blit; `g.ssao` flag + radius/strength/algorithm wired to the existing settings path.
Risk/pitfall: the glTF PBR renderer's PS-footer override only sees variables in scope at the end of `main()` — the final world-space normal variable name must be located in the GLTF_PBR source (and the shadow-pass PSO must be flagged so `SV_Target2` isn't written there); every PS that draws into the 3-RTV world pass must write `SV_Target2` (including UNSHADED glTF mode and any fallback/debug draws) or the output is undefined.
Effort: medium — 4 subtasks, each independently verifiable.

**B. Depth-derived normals (no world-pass changes).**
Sketch: a small pre-SSAO pass that finite-differences the D32 SRV to reconstruct normals and feeds that into `pNormalBufferSRV`; everything else as A.
Risk/pitfall: faceted/noisy normals from D32 degrade GTAO horizon integration noticeably (terrain is a smooth heightmap where per-vertex normals are far better; props have real mesh normals we'd be throwing away); an extra full pass; deviates from the reference integration (Hydrogent feeds a true G-Buffer normal RT, HnPostProcessTask.cpp:829).
Effort: smaller (skips subtask 1's shader changes) but worse quality; only justified if approach A's shader surgery proves too invasive.

**C. Pre-TAA AO multiply (composite AO'd color into the TAA input).**
Sketch: same as A but the composite runs on `sceneColorTex` before the TAA block, so TAA also filters AO.
Risk/pitfall: two competing temporal filters — TAA variance-rejection treats AO disocclusion edges as color noise (banding/ghosting) and TAA motion reprojection smears AO at moving edges; exactly the double-history problem engines avoid.
Effort: equal to A; strictly worse stability profile. Rejected.

**D. In-world-pass AO (sample AO in the world PS).**
Sketch: feed AO into lighting where it belongs (diffuse term per the README formula).
Risk/pitfall: not possible — AO requires the final world depth, which only exists after the world pass; would need a deferred AO re-light pass, a wholesale pipeline change.
Effort: large; rejected for this task.

## Recommended approach

**A.** The integration surface is already 90% built: one shared PostFXContext, one depth SRV, one dangling settings flag, and the exact PS-source-surgery precedent for adding a second SV_Target — so the whole task is "one RTV + three small shader edits + one module + one composite PS", each verifiable in isolation (RenderDoc pass names, normal-RT dump, before/after screenshots). It must be true that: (1) the GLTF_PBR PS source exposes (or can expose via the existing `GetPSMainSource` hook) a world-space normal in footer scope and its PSO flags can gate the shadow pass off; (2) all three world passes write `SV_Target2` in every variant they draw with the 3-RTV configuration; (3) `PostFXContext::Execute` runs before the SSAO `Execute` (it does — TAA already calls it in `taaWorldResolve`). If (1) fails, fall back to B for the normal source only.
