## brainstorm

## Core difficulty

Perceptual silhouette problem, not a render bug: with the hard `tex.a < 0.5` cutout
(`props_ps.hlsl`, flag bit 0), each card's visible shape is exactly the set of ≥0.5-alpha
texels in its sampled sub-rect. With the current sparse 128px texture (70 large leaflets,
84px-tall region) and 45-90% random sub-rect sampling, each card shows 1-3 big leaflets
clipped to an arbitrary rectangle — literally square planes. The reference
(/var/home/enes/Downloads/tree.png) hides card boundaries purely by ~16-way overlap of
full-texture "leaf cluster" sprites whose individual silhouettes are irregular (never
rectangular).

## Reductions / key lemmas

1. **Card-silhouette invariant.** Visible card shape = {texels: a ≥ 0.5} inside the sampled
   rect. A non-rectangular silhouette is only guaranteed when the alpha content does NOT
   reach the sampled-rect border, i.e. the card must sample a region whose content has a
   transparent moat around the region boundary → each card = one complete leaf-cluster
   sprite sampled full-region (exactly what ez-tree does: every card shows the whole LFS
   sprite). This corrects the plan's wording "filling the sampled region edge-to-edge":
   an edge-to-edge dense field makes the cutout silhouette a SOLID RECTANGLE — the worst
   case of the reported symptom. Keep the plan's density goal, but as one dense cluster
   with a guaranteed moat, sampled whole.
2. **Mip invariant.** The leaf texture is created with `GenerateMips=True` and the base
   sampler is full trilinear (`PropsRenderDiligent.cpp:230`, `g_BaseSampler`). Coarse mips
   average alpha: with the current sparse texture, minified cards average <0.5 alpha and
   mostly vanish/flicker at distance. The cluster core must be dense enough (~70%+ fill)
   that the ≥0.5 cutout survives mip downsampling to ~mip 3-4. (The 256px canvas helps:
   finer leaflets, more mip levels.)
3. **Tri-budget correction (plan is wrong here).** `maxTris` caps the WHOLE tree
   (branches + leaves): `Gen::room` in `TreeGen.cpp:86` makes `emitCards` return early when
   the cap is hit → bare tips. Measured: 2352 total tris with only ~250-380 of them leaves.
   12-16 cards/tip × 32 tips × 4 tris/card = 1500-2000 leaf tris → total ~3800-4100 >
   3300 cap. So raising `maxTris` (→ ~6000) is MANDATORY with the card-count increase, or
   the tree will silently lose tips' foliage. The plan's "plenty of budget" is false
   (2352 is already 71% of 3300).
4. **Density vs silhouette trade-off resolves via overlap.** A single card must look
   irregular (lemma 1); the CANOPY must look continuous — that comes from 12-16 cards/tip
   overlapping so the union silhouette is fluffy. Card size must NOT grow (0.055 ≈ 5.5%
   of tree height already matches the original's 5-6%); density + sprite content do the
   work. Per-card variety exists already (az rotation, tilt ±0.45, size ±60%) and is
   enough — no new generator machinery needed.
5. **Safety boundary.** Only DECIDUOUS uses a leaf texture (`Game.cpp:90`:
   `r.species == AZGAAR_PROP_DECIDUOUS ? "images/leaf-textures/ash.png" : nullptr`) and only
   `LeafStrategy::CARDS` uses `kBarkUvRect`/`kLeafUvRect` (`TreeGen.cpp:347`); conifer/
   acacia/shrub are untextured BLOBS/CONES/FAN using `kFullUvRect`. Regenerating ash.png
   and retuning the two UV rects cannot affect other species; only `configDeciduous()`
   constants are touched.

## Candidate approaches

A. **Cluster-sprite approach (recommended).** Full-region sampling per card + regenerate
   ash.png as ONE dense leaf cluster (many small leaflets, ~70-85% core fill, fluffy
   outline, transparent moat around the region border, 256px canvas) + cardCountMin/Max
   1/2 → ~11/15 (12-16 cards/tip) + maxTris 3300 → 6000. Risk: sprite repetition visible
   at close range (mitigated by existing per-card rotation/scale/tilt variance; the
   original had the same property and reads fine). Effort: 1 config change, 1 small
   emitCards change, 1 script rewrite, 1 repack, screenshot iteration.

B. **Dense-tangle field + keep sub-rect sampling.** 256px texture as a uniform dense field
   of tiny leaflets; keep 45-90% sub-rect sampling; raise card count. Risk: every card's
   cutout silhouette is a hard rectangle (content always reaches the crop border); the
   canopy's outer boundary shows square edges — the exact reported symptom survives,
   just smaller. Effort: similar to A but likely to fail the visual test.

C. **Per-vertex alpha soft-mask + dense field.** Encode a radial falloff into card vertex
   alpha so the cutout boundary becomes an ellipse. Risk: the cutout tests `tex.a` only
   (`props_ps.hlsl`), vertex color alpha is multiplied after the discard — so this
   requires shader/PSO changes (and possibly a new flag bit), far more moving parts for
   a result B/A can approximate. Effort: 2-3× A.

D. **Replace cards with geometry (BLOBS/FAN) foliage.** Denser, irregular by
   construction. Risk: abandons the ported design, costs ~4-8× more tris, loses the
   reference's texture-driven look. Effort: high, low fit.

## Recommended approach

A. For it to work: (1) each card samples the leaf region whole (fw=fh=1.0, optional
0.9-1.0 centered crop for variety) so its cutout silhouette is the cluster's fluffy
outline, never a rectangle; (2) the regenerated texture's cluster fills ~70-85% of the
region core with a guaranteed transparent moat around the region border (so no arbitrary
sampled sub-rect can produce a solid rect, and coarse mips stay ≥0.5 in the core);
(3) maxTris is raised BEFORE or WITH the card-count increase so `g.room()` never clips
tips; (4) only `configDeciduous()`, `emitCards` sampling, `make_leaf_sprite.py`, and the
two UV-rect constants change — renderer, pak loader, and other species untouched.
