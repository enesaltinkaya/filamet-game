# notes

## brainstorm

## Core difficulty

The cliff band in `splat_terrain_ps.hlsl` (c-game/data/pak_1, lines 348/355) samples `g_CliffAlbedo`/`g_CliffNormal` with the same pure XZ world projection (`tiledUV`) used by the flat splat chain, so steep normals compress/stretch the UV; the fix is slope-weighted triplanar projection, which the old engine already implemented — the hard part is not the algorithm but porting the *scale* correctly: the old engine's `CLIFF_TRIPLANAR_SCALE = AZGAAR_CLIFF_DETAIL_TILE / 4096 = 32/4096 = 1/128` is a meters⁻¹ world scale (one repeat per 128 m), *not* a pixels-based constant. The new cliff texture is 1024×1024 (verified from the ktx2 header at `c-game/data/pak_1/images/terrain/cliff_side_default/albedo.ktx2`), so naively porting `32/4096`-style "tiles/texture-size" arithmetic would give a 32 km repeat; the correct port is `uv = worldPos / SPLAT_CLIFF_METERS` with `SPLAT_CLIFF_METERS = 128.0`.

## Reductions / key lemmas

- Triplanar projection with weights `w = pow(abs(N), 4.0)` (normalized, `N = normalize(In.WorldNormal)`) removes the stretch because the dominant projection axis is the one perpendicular to the surface normal; at `|N|`-dominated vertical faces the XZ projection's weight → 0.
- The world scale is texture-resolution-independent: period = 1/scale (m). Old engine: 4096 px at scale 1/128 → 128 m/repeat; new engine: 1024 px at the same scale → same 128 m/repeat (8 px/m vs 32 px/m — pattern density identical, effective pixel density 4× coarser, acceptable since the texture asset is what it is).
- Per-face uvs are linear in world position (`zy`, `xz`, `xy` × constant scale), so constant-Jacobian sampling is fine with the existing REPEAT+aniso `g_DetailSampler`; `SampleGrad` with constant grads or plain `Sample` both work. No new sampler or C++ resource change needed — `g_CliffAlbedo`/`g_CliffNormal` bindings already exist (`SplatTerrainDiligent.cpp` lines 1309–1311, band dirs line 752).
- The normal blend must stay in the existing tangent space (`nT` relative to the glTF tangent frame, lines 362–365). Do *not* port the old engine's TBN-construction path (`buildTerrainTBN`) — mixing world-space normals into `nT` would corrupt the perturb.
- `wCliff = smoothstep(SPLAT_CLIFF_LO, SPLAT_CLIFF_HI, slope)` (line 343) and the albedo/nT blend lines (348–349, 355–356) stay untouched — only the *sampling* changes, so sand/snow/splat bands are structurally unaffected.
- An env-var override pattern already exists (`ENGINE_SPLAT_DETAIL_METERS` → prepended `#define`, plus the `ENGINE_SPLAT_CLIFF_LO/HI` table at lines 1009–1034), so cliff scale/tiling can be tuned without repacking.

## Candidate approaches

1. **In-shader triplanar (recommended).** Replace the two cliff `SampleGrad(g_DetailSampler, tiledUV, du, dv)` calls with a 3-projection triplanar sample of `g_CliffAlbedo`/`g_CliffNormal` at `worldPos = In.AnchoredPos + g_Anchor` (the absolute world position already derived at lines 306/339), weights `pow(abs(normalize(In.WorldNormal)), 4.0)`, scale `1/128.0`. ~25-line shader-only edit; zero C++/resource changes. Risk: triplanar seams on 45° faces (mitigated by the sharpness-4 weighting) and 4×-coarser effective pixel density vs the old 4096 px texture — a cosmetic ceiling, not a correctness issue. Effort: small (one file, one build, one screenshot).
2. **Cylindrical/normal-based 2D projection (project onto plane perpendicular to N with a 2D basis).** Cheaper (1 sample per map), no seams, but on a real 3D hill it distorts along the circumferential axis and is more code to get the basis right; the reference behavior is triplanar, so we'd lose parity. Risk: harder to match the old engine's look. Effort: small-medium.
3. **Bake a world-projected "cliff-space" texture / vertex-bake UVs.** Correct and cheap at runtime, but requires pipeline work (bake tool or VS attribute) far beyond the scope of a texture-stretch fix. Effort: large.
4. **Just lower SPLAT_CLIFF_HI / raise SPLAT_CLIFF_LO to hide the effect.** Not a fix — the band is needed on the hill; it would only trade stretch for missing cliff coverage. Effort: trivial, wrong.

## Recommended approach

Approach 1: triplanar sampling inside `splat_terrain_ps.hlsl`, porting the old engine's exact weighting (`pow(abs(N), 4.0)`, normalized) and exact world scale (period 128 m → `uv = worldPos / SPLAT_CLIFF_METERS`, `SPLAT_CLIFF_METERS = 128.0` behind `#ifndef`), applied to both cliff albedo and cliff normal, blended into `albedo`/`nT` through the existing `wCliff` smoothstep. It is the minimal diff that restores the reference behavior, needs no C++/resource/sampler changes, and is fully A/B-verifiable with headless screenshots. For it to work: `In.WorldNormal` must be the un-perturbed geometry normal (it is — used for `slope` at line 340, before the nT perturb at line 365), and the world position must be the absolute one (`AnchoredPos + g_Anchor`, consistent with lines 306/339) so the pattern stays anchored across world rebuilds, mirroring the existing `tiledUV` rationale.
