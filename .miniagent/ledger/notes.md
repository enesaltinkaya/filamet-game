## brainstorm

## Core difficulty

The splat-terrain shadow fix (caster depth pass + per-pixel cascade receive with PCF/VSM/EVSM2/EVSM4 branches) is already uncommitted in the working tree, so the task is not "implement" but "prove a four-mode fix end-to-end headless" — and the failure signatures (no shadow / peter-pan / acne / light bleed) have three independent root-cause families (stale repacked pak, generator side in thirdparty DiligentFX, receiver side in the splat PS) that all look the same in a final screenshot, making a cheap first fork the only way to avoid burning RenderDoc sessions.

## Reductions / key lemmas

- **Verified in-tree state (this pass):** `splat_terrain_ps.hlsl` has `filterShadowPCF3` (:289), `filterShadowVSM` (:327), `filterShadowEVSM` (:396) with an `if (evsm4)` gate so EVSM2 on RG32 never reads `.zw`; filterable branches feed **raw `cascadeNdc.z`** (no `fFixedDepthBias` — the variance floor is the bias), PCF feeds `cascadeNdc.z - sBiasParams.y`; mode comes from `f4ShadowFade.y`; per-pixel cascade pick from `f4CascadeCamSpaceZEnd` is shared across all modes; out-of-cascade-box pixels stay lit; tier fade over the last 25% of `f4ShadowFade.x`. Caster: `splat_terrain_shadow_{vs,ps}.hlsl` (trivial depth-only PS) + `splatTerrainShadowDrawDiligent` called from `renderCascadesImpl` after the player draw (:412-414).
- **Binding correctness (checked):** `shadowDiligentShadowSRV()` is mode-aware — `curMode == 1 ? mgr.GetSRV() : mgr.GetFilterableSRV()` (ShadowDiligent.cpp:662) — so `SplatTerrainDiligent.cpp:1523` binding it to the linear slot in modes 2-4 is correct, and the linear clamp sampler (`:1191`) is what the PS's `g_ShadowMapLinearSampler` needs. Generator: `createShadowMap` sets `Is32BitFilterableFmt=true` → VSM/EVSM2 = RG32, EVSM4 = RGBA32; constants `fVSMBias=1e-4`, `fEVSMPositiveExponent=40`, `fEVSMNegativeExponent=5`, `bIs32BitEVSM=1`.
- **Repack mechanics (checked):** `scripts/build.sh` runs `data.sh` for both c-game and c-engine with `BIN_DIR=build/c-game`, `RELEASE=0`; `data.sh` repacks when the tar-content md5 changes, so the edited `c-game/data/pak_1/materials/*.hlsl` will repack automatically — but the md5 cache (`scripts/.tmp`) is only trustworthy if last written by build.sh itself. A manual/failed `data.sh` run with a different `BIN_DIR` poisons it and later runs silently skip repack. Cheap discriminator: build log must contain "zipping data/pak_1".
- **The fork:** if PCF (mode 1) is broken on the new splat terrain, the filterable modes can't be the real problem — the shared caster, cascade pick, or repack is. Proving mode 1 + mode 0 (control) first isolates the receiver-only branches for 2-4.
- **Mode 0 is a mandatory control:** a dark region in the overlay shot in modes 2-4 could be SSAO/fog/IBL, not shadow; only the 1-vs-{2,3,4} diff with 0 showing nothing separates "shadow works" from "something else darkened the ground".
- **Screenshot timing caveat:** `ENGINE_SCREENSHOT` fires a few frames after startup; splat terrain chunks stream in, so a capture before streaming shows empty ground and the parity check false-fails. Symptom: no terrain at all in the shot. Remedy is just a relaunch (one-shot capture), not a code change.

## Candidate approaches

1. **Prove-the-fix sweep (plan's strategy):** build, then headless boot of modes 0-4 with pinned teleport + `ENGINE_SPLAT_SHADOW_DEBUG=2` overlay screenshots; judge mask parity vs mode 1; RenderDoc only for failing modes. Risk: screenshot-timing/streaming-in false negatives; mitigated by verifying each shot actually contains terrain + the caster's shadow region before judging. Effort: low.
2. **RenderDoc-first:** capture all 4 modes up front, dump `shadow` + `world` passes, verify atlas format/moments per mode before eyeballing anything. More diagnostic authority, but ~400 MB + replay per mode on a path that is likely already correct; wasteful if the sweep passes. Effort: medium-high.
3. **PCF-forked sweep:** run mode 0 + mode 1 first as a fork; only if both pass (mode 1 shows the dark region, mode 0 shows none) sweep 2-4; any mode-1 failure stops the sweep and reframes the task (caster/pick/repack, not VSM math). Strictly a smarter ordering of approach 1 with a decision gate. Effort: low.
4. **Add a headless self-test** (log per-frame mean attenuation per mode, or CPU-sample the filterable atlas). Over-engineered for a one-off verification; the overlay screenshot already is the measurement. Effort: high, rejected.

## Recommended approach

Approach 3 (PCF-forked sweep), i.e. the plan's task list with the explicit mode-0/mode-1 gate in front and the repack check inside task 1. The fix is already in the tree and every structural wiring point that a single pass would re-derive has now been verified, so the expected path is "sweep passes → final mode-1 look check → done"; the RenderDoc path (task 3) exists only for a flagged mode, where its atlas-dump authority actually earns its cost. For it to work: the build must repack pak_1 (log evidence), each overlay shot must contain streamed-in terrain and the player caster's shadow (else relaunch once, not re-debug), and parity is judged as "dark region same shape/extent as mode 1, softer allowed" — not pixel-identical, because VSM/EVSM filtering legitimately changes edge softness.

## Proposed tasks

1. **Build with repack evidence:** `./scripts/build.sh`; confirm the log contains "zipping data/pak_1" (shader edits force the md5 change) and that the final binary is fresh. If the repack line is absent, force it: `cd c-game && RELEASE=1 BIN_DIR=$(pwd)/../build/c-game ../scripts/data.sh` from c-game/ (and same for c-engine), then re-run build.sh.
2. **Fork sweep (modes 0 and 1 first):** for N in 0 1: `TERM=xterm-256color ENGINE_AUTOTEST=enter ENGINE_HIDDEN_WINDOW=1 VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/radeon_icd.json ENGINE_SHADOW_MODE=$N ENGINE_TELEPORT=180,640,180 ENGINE_SPLAT_SHADOW_DEBUG=2 ENGINE_SCREENSHOT=/tmp/shm$N.jpg ./build/c-game/c-game`. Check: "shadow: mode N" log line (mode 0 logs "shadow: disabled"), zero VUIDs, shot contains terrain; /tmp/shm0.jpg has no dark shadow region under the player, /tmp/shm1.jpg has one. If mode 1 shows no region, STOP — this is caster/cascade-pick/repack, not a filterable-math issue; flag and reframe.
3. **Filterable sweep + parity judgment (only if task 2 passed):** same run for N=2,3,4 → /tmp/shm2..4.jpg; each must show a dark terrain shadow region of the same shape/extent as /tmp/shm1.jpg (softer edges allowed, no acne/light-bleed in lit areas, no new VUIDs); flag any failing or marginal mode with a hypothesis note (acne→receiver bias/variance floor; peter-pan→bias still applied or caster bias; no shadow at all→generator/atlas).
4. **Failure-only RenderDoc + final look:** only if task 3 flagged a mode: `./scripts/run.sh renderdoc` (sets LD_PRELOAD + layer; ~400 MB capture in /tmp/RenderDoc/, clean old ones) with the failing `ENGINE_SHADOW_MODE`, then `scripts/rdc.py dump shadow` (verify caster drew + atlas has non-trivial moments) and `dump world` (verify receiver readback); one coherent fix in the splat PS branch or ShadowDiligent.cpp `fVSMBias`/exponents, rebuild, re-sweep that mode only. Finish unconditionally with an un-overlaid mode-1 shot (/tmp/shm_final.jpg, no ENGINE_SPLAT_SHADOW_DEBUG) confirming shipping look, `settings.json` `shadowMode=1`, and per-mode verdicts.
