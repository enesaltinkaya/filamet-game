# Plan: DiligentFX Screen-Space Ambient Occlusion — detailed implementation plan

## Strategy

The task is a planning task: the deliverable is a detailed implementation plan (in `plans/ssao-diligentfx.md`, matching the existing plan docs in `plans/`) for integrating DiligentFX's `ScreenSpaceAmbientOcclusion` into c-engine's Diligent backend, grounded in inspection of the three referenced reference trees (Tutorial27, DiligentFX SSAO, Radient/Hydrogent) and the engine's current render pipeline. The good news is the integration surface is nearly ready: c-engine already links the prebuilt `libDiligentFX.a` (which contains `Diligent::ScreenSpaceAmbientOcclusion` symbols), already runs a `PostFXContext`-based TAA pass (`TaaDiligent.cpp`) with a double-buffered D32 depth texture created with `BIND_DEPTH_STENCIL | BIND_SHADER_RESOURCE` (the exact `pCurrDepthBufferSRV` input SSAO needs), and an unconsumed `ssao` graphics-setting flag already flows through `Renderer.cpp` / `DebugGui.cpp` / `SettingsGraphicsGui.cpp`. The two real gaps the plan must solve are (1) a world-space normal buffer — DiligentFX SSAO requires one and Hydrogent proves it comes from a G-Buffer RT the scene passes write — and (2) applying the resulting AO texture to the already-lit world color before TAA resolve/blit. The plan must therefore be phased: reference inspection findings, normal-buffer RT + shader output changes, SSAO init/prepare/execute pass insertion between the `props` and `taa_resolve` debug groups, AO compositing, settings/debug-GUI wiring, and RenderDoc/screenshot verification. Every claim in the plan must cite the file/line it came from, so a later implementation worker can execute it without re-deriving anything.

## Approach

- Worker 1 inspects `DiligentSamples/Tutorials/Tutorial27_PostProcessing` (readme + src) and records the canonical `PostFXContext` integration shape; compare against `c-engine/renderer/diligent/TaaDiligent.cpp` (already the "Tutorial27 integration shape" per its header comment) and list what is reusable as-is.
- Worker 2 inspects `DiligentFX/PostProcess/ScreenSpaceAmbientOcclusion` (README, `interface/ScreenSpaceAmbientOcclusion.hpp`, `src/ScreenSpaceAmbientOcclusion.cpp`, `Shaders/PostProcess/ScreenSpaceAmbientOcclusion/public/*.fxh`) and records the full API surface: `CreateInfo{EnableAsyncCreation}`, `PrepareResources(device, ctx, PostFXContext, FEATURE_FLAGS)`, `Execute(RenderAttributes{pDevice, pStateCache, pDeviceContext, pPostFXContext, pDepthBufferSRV, pNormalBufferSRV, pSSAOAttribs})`, `GetAmbientOcclusionSRV()`, `UpdateUI`, the `SSAO_ALGORITHM_*` / `ALGORITHM_TYPE` GTAO/HBAO/VBAO options, `FEATURE_FLAG_HALF_PRECISION_DEPTH` / `FEATURE_FLAG_HALF_RESOLUTION`, and the 8 internal compute techniques (downsampled depth → prefiltered depth → AO → temporal accumulation → convolved/resampled history → spatial reconstruction → bilateral upsampling). Input contracts: depth 1×F32, normals 3×float in [-1,1] world space.
- Worker 3 inspects the full-engine wiring: `DiligentFX/Hydrogent/src/Tasks/HnPostProcessTask.cpp` (GBuffer `GBUFFER_TARGET_NORMAL` feeding `pNormalBufferSRV`, AO multiplied into the main lighting pass via `g_SSAO`, depth SRV taken from `FrameTargets->DepthDSV`) and `DiligentFX/Radient` (`RadientPostFXParameters.{hpp,cpp}`, `RadientTesseraPostProcessPipeline.{hpp,cpp}`) for how a production engine parameterizes and exposes SSAO.
- Worker 4 inventories the c-engine side: `TaaDiligent.cpp` offscreen chain (`sceneColorTex` RGBA16F, `motionTex` RG16F, `depthTex[2]` D32 with shader-resource SRV already passed to `PostFXContext`), `DiligentRenderer.cpp` pass order (`shadow` → `player` → `terrain` → `props` → `taa_resolve` → `gui` → `rmlui`), the world-pass HLSL shaders (`renderer/diligent/shaders/heightmap_terrain_ps.hlsl`, `props_ps.hlsl`, player pass) and the CMake custom command that copies them into `c-game/data/pak_1/materials/`, and the dangling `g.ssao` flag path (`Renderer.cpp:234` reads `aoDisabled`, `DebugGui.cpp:65,103`, `SettingsGraphicsGui.cpp:116`).
- Worker 5 writes `plans/ssao-diligentfx.md` as a phased, file-level plan covering: (a) normal buffer — new RGBA16F/RGB16F normal RTV added to the offscreen world chain, world-space normal output added to terrain/props/player PS, shader-rebuild/pak-copy step; (b) SSAO pass — `SsaoDiligent.{h,cpp}` module mirroring `TaaDiligent`, init via existing `PostFXContext`, `PrepareResources` on resize, per-frame `Execute` after `props` and before `taa_resolve`, half-resolution + GTAO defaults; (c) AO application — composite world color × AO before TAA resolve/blit (respecting `renderScale`, keep UI passes full-res); (d) settings — wire the existing `ssao` flag plus radius/algorithm params into `applyGraphicsSettings` / DebugGui / graphics settings page; (e) verification — RenderDoc capture naming the new SSAO pass (DiligentFX groups its compute dispatches; confirm via `scripts/rdc.py list`), `ENGINE_SCREENSHOT` before/after frames, and known-pitfall check against `docs/lessons.md`. Include risks: D32-as-SRV sampling on Vulkan (works for TAA reprojection today — confirm SSAO's depth read works identically), TAA/SSAO jitter interaction (SSAO has no external jitter input; stability handled internally), normal RT cost at full vs render-scaled resolution, and the `--start-group` link line in `c-game` if new DiligentFX symbols surface.
