# Plan

Goal: make our procedurally generated trees (c-utils/treegen) match the ez-tree reference look — the reference (tree.png) is a medium deciduous tree: a thin, tall trunk with 3–4 major forks high up and a dense canopy of small leaf clusters — while ours currently render as chunky low-poly angular green masses (screenshot in task.md).

Research (tasks 1–2, done) found the reference is the ez-tree demo's "Ash Medium" preset: /tmp/ez-tree/src/lib/presets/ash_medium.json (seed 36330), generated by the deciduous mode of /tmp/ez-tree/src/lib/tree.js — full parameter values and structure semantics are in notes.md. Strategy: diff parameters, don't rewrite. Our TreeGen port is missing (a) the terminal twig/continuation layer that produces ~112 thin leaf twigs (we have 8 tips), (b) stratified child placement + relative child radii + smooth 12-segment trunk, and (c) the actual leaf style — the reference canopy is alpha-tested crossed billboard quads of a leaflet sprite, not low-poly spheres.

Approach: (3) restructure the deciduous branch config/generation to the Ash Medium ratios (tall thin trunk, side branches from 0.23, 7/4/3-ish counts scaled to tri budget, ~48/75 deg angles, 0.7 taper, thin terminal twigs); (6) add a small crossed-billboard leaf strategy per twig; (7) generate an ash-like leaflet-cluster sprite PNG (the real one is a git-lfs pointer locally) and wire it in through the existing alpha-tested prop-texture/grass-card path; then (5) rebuild, capture via ENGINE_SCREENSHOT, and iterate against tree.png.
