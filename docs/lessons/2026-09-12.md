- RenderDoc per-event GPU durations on this setup can be flat-out misattributed, not just overlapping: contiguous unrelated draws (36-index and 490k-index alike) all report the same ~10.5 ms in a smoothly decaying plateau, pass sums (186 ms) exceed any real frame, while the engine's own whole-frame `QUERY_TYPE_DURATION` reads 1.8 ms — don't conclude anything from rdc.py/`EventGPUDuration` absolute values here; A/B with the StatsGui `gpu:` number (Diligent duration query around the frame, visible via `ENGINE_STATS_GUI=1` or the screenshot HUD) or wall-clock frame counts
- Shader-cost A/B trick for features with a distance fade: force the feature onto every pixel with its env tuning (e.g. `ENGINE_SPLAT_POM_FADE_START=0 ENGINE_SPLAT_POM_FADE_END=1000000`) instead of moving the parked camera — same view, full-cost path, and `ENGINE_SPLAT_POM=0` gives the disabled baseline; incident: "pom is taking absurd amount of gpu time" — forced-fade measured POM at ~9 of 10.9 ms/frame (83 %), caused by 45 aniso-16 `SampleGrad` fetches per march tap (5-tap blur × 9-texture chain, ≤13 taps/px); fixed with a dedicated bilinear `g_HeightSampler` for height taps + single-tap march at 2× widened gradients (`ENGINE_SPLAT_POM_BLUR=1` restores the exact legacy 5-tap kernel), POM cost now ≈ noise at the same forced-fade setting
- Terrain "no specular anywhere" means check the albedo ALPHA on the GPU first, not the shader math: the splat PS reads roughness from `albedo.a` (old-engine bake convention `albedo.a = roughness`), and a `convert("RGBA")`-style bake over alpha-less source albedos silently writes 255 = roughness 1.0 — the Cook-Torrance path is then correct and permanently dark; incident: painted detail sets (grass1/roads1) had flat-alpha albedo.ktx2, `ENGINE_SPLAT_SHADOW_DEBUG=100` (PS outputs `roughness`) rendered pure white while the on-disk source roughness maps were never consumed; fix = `findRoughnessMap` in blender-terrain.py writes the rough map into the albedo alpha (`--details-only` rebakes)
- PIL `Image.open(16-bit PNG).convert("L")` clamps every texel to 255 (I;16 → L saturates, no rescale): roughness/POM-height bakes from 16-bit ambientCG-style sources come out fully white/flat; rescale via numpy (`>>8` for true 16-bit range, min-max normalize for `I`); incident: rocky_terrain rough baked as opaque 255 and its 16-bit disp baked as flat POM height until `loadGrayscaleL8` was added
