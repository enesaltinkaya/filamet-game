# 2026-09-09

- Porting ez-tree presets to `treegen`: convert the numbers, don't transcribe them. ez-tree works in preset world units (ash_medium: trunk radius 2.0 at total height 66.4, twist 0.09/section, gnarliness per section scaled by `max(1, 1/sqrt(r_meters))`), while `treegen::generate` normalizes to unit height and applies gnarliness as `g / max(0.15, sqrt(r_unit))` per section — so the same raw value lands 2-3× stronger on thin twigs. Fingerprint of an unconverted port: stocky trunk (54% too fat), helical twist (twist is per-section in ez — 0.09×12 sections = 1.08 total), gnarled mid-branches, crown reading as a "candelabra with pom-poms" instead of the reference's slender oval. Convert: baseRadius = preset radius / preset total height (0.030), twist × section count (1.08 / -0.56), gnarliness ÷ measured divisor per level (0.005 / 0.035 / 0.028 / 0.010). Incident: "deciduous trees don't look like ez-tree default ash medium" — structure matched after conversion + cardSize measured from the reference GLB (2.67/82 ≈ 0.033) instead of assumed.
- `treegen` leaf-card budget: raising per-tip card count silently re-clips the crown when `maxTris` isn't raised — `Gen::room()` drops the last branches' cards and the build log line shows the deciduous variant at exactly `maxTris` (fingerprint: `deciduous/N=20000` after bumping cardCount; was 19384 before). Keep `maxTris` ≥ branches + tips×cards×8.
