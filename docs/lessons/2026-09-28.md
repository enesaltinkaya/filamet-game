# 2026-09-28

- TAA camera jitter must be APERIODIC and thin hard-edged transparent geometry must not be jittered; the PBR motion vector must be the TOTAL apparent screen motion (currNDC − prevNDC, jitter delta INCLUDED), not the jitter-subtracted scene motion. DiligentFX's `GetJitterOffset` runs a 16-sample Halton table (`SampleCount = 16` in the prebuilt .a — the git source says the same), so the camera jitter is a 16-frame periodic sub-pixel oscillation (3.75 Hz at 60 fps) — exactly in the visible-flicker band, and close enough to the TAA first-order IIR's corner (τ ≈ 1/(1−0.9) ≈ 11 frames) that the filter passes ~26% of the oscillation (|H| = (1−w)/√(1+w²−2w·cos(2π/16)) = 0.26) instead of attenuating it. In a static scene the 1 px hard-edged transparent grass planes' edges then enter/exit pixels on the repeating 16-phase pattern, and the per-pixel ON/OFF flip is full-contrast — the flicker amplitude does NOT scale with the jitter range (measured: median 42/255 per consecutive frame at jitter scale 1.0×, 0.25× AND 0.125×; only the pixel COUNT drops), because a flip is a flip. Fingerprint: `ENGINE_JITTER_DUMP` shows the (x,y) pair repeating exactly every 16 frames; world-pass color is bit-stable between same-phase frames (f120 vs f136: 2 px) and differs on every other phase pair; the TAA history is healthy (alpha ≈ taaWeight ≈ 0.900 everywhere, RGB bit-stable f299→f300) so it is NOT a history-rejection bug — the drive signal is periodic; taaWeight 0.9→0.95, RCAS off, adaptive-clamp off, and the jitter-subtracted→total MV change each buy only 9–27% (the leak is the IIR's white-noise response + sRGB gamma re-amplifying dark midtones, not any single knob). Fix (all engine-side, no DiligentFX rebuild): (1) `taaJitterOffset` in TaaDiligent.cpp replaces `taa->GetJitterOffset()` with an engine-owned 1024-sample Halton (same formula, `ENGINE_JITTER_SAMPLES` to A/B, default 1024) — the "flicker" becomes a 0.06 Hz wander the eye integrates; (2) default jitter scale 0.25 (`ENGINE_JITTER_SCALE`); (3) RenderPBR.psh line 610 uses the 2-arg `GetMotionVector(ClipPos, PrevClipPos)` so TAA reprojects the history by the true apparent motion (the jitter-subtracted version reads 0 on a static scene and samples the differently-jittered history misaligned by up to half a pixel); (4) props (the transparent grass planes, sceneModels i>0) draw with an UNJITTERED frame-attribs copy (`fillFrameAttribsUnjittered`: proj minus currJitter, f2Jitter 0, PrevCamera unjittered with its own f2Jitter) — static unjittered geometry gets MV=0 and a perfectly aligned history, so the 1 px edges can never flip. Measured result (consecutive-frame final-image diff, grass mask minus player band and FPS text): 7.2–10.6k px >16/255 (median 42) → 0 px. The player band keeps flickering in BOTH TAA modes (≈1.5–3.6k px) — that is the parked character's real `ANIM_IDLE` (wall-clock dt-driven, `playerUpdateAnimation`), not a TAA artifact; the top-left blob in any burst diff is the `showFps` counter. Caveat: the stride-8 burst metric (max−min over 8 frames) LIES about periodic jitter — stride 8 aliases a 16-period to 2 phases, so compare CONSECUTIVE frames for perceptual flicker.
