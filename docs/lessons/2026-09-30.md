- "Small triangle-shaped shadow, top-right of screen, over terrain, gone with shadows off" = cascade NEAR-plane cross-section: ring cascade z windows are `plz ± 2·radius` (light-z centred on the player), so terrain/props between the sun and the cascade get clipped at the near plane and write depth ≈0 across their projected area — a planar occluder that covers every receiver behind it, with straight box-face edges. Measured signature in the atlas: the map corner holds depth 0.008 (cascade 1, prop write) / 0.298 (cascade 0, cliff write) at the corner texel, and per-draw bisect attributes it to the first caster of that slice. Fix in the ring block: `nearPad = 2·radius·ENGINE_SHADOW_NEAR_PAD` (default 3) dilates the window to `plz − 2r − nearPad … plz + 2r`, putting every caster that can cast into the cascade (cliff base 25 m, cliff wall 850 m, mountains 700 m here) inside the window as a real occluder; the cull follows the caster matrix for free. Cost is depth-only: cascade-0 z quantization 1.2 → 2.3 cm/texel (window 24 → 48 m); PCF slope bias scales with the window (margin 12 → 24 cm), EVSM variance floor scales in world units. A VSM-mode Chebyshev floor of 1e-4 in normalized window units bleeds ≈1 % of window (16 m at cascade 2): VSM needs the floor rescaled per window if mode 2 is ever the shipping mode.

- An FX `.fxh` edit that visibly changes NOTHING is the shader cache, not the edit: the cache key hashes the top-level source the stream factory resolves (a `.fx` is only the top of its include chain), so every DiligentFX include change serves stale SPIR-V. Fingerprint: same build, same frame, cached vs `ENGINE_NO_SHADER_CACHE=1` — 91 % of pixels differ (measured on a props-receiver PCF kernel change); the props path also responds to knobs it does not read (the dither) because the CPU-side cascade pick is doing the visible work. Fix: fold the source the compiler actually reads into the key. Keying it on the raw `Shaders/` tree is actively WRONG — the FX factory serves the build-time `shaders_inc` blobs, so an edit that has not been rebuilt moves the key while the compiled bytes are still the old ones, and the stale SPIR-V gets stored under the new key and survives the rebuild (measured: a props-receiver gate relaxation stayed invisible for three runs; the cached EVSM2 render measured 2.014 gray for the player's shadow, the same binary with the cache bypassed 13.762). Rule: fingerprint `shaders_inc/*.h` (`DILIGENT_FX_SHADER_INC_DIR`), never the source tree. A new FX edit costs one ~4 s recompile at startup; the warm run then matches the no-cache run on 99.97 % of pixels (`ENGINE_SHADER_CACHE_TRACE=1` prints each key).
